# 撮合模擬規格

`osmium-matching` 的精確行為。交易所規則的出處、生效日期與信心等級記錄在
[撮合規則研究](../design/research/matching-rules.md)（以下寫作「研究 §n」）；本頁只寫模擬器怎麼做。
設計決策見 [ADR-0008](../design/decisions/0008-full-market-matching-simulation.md)。

狀態：規格已定案，實作進行中（見[架構的遷移狀態](../design/architecture.md#遷移狀態)）。

## 1. 基本假設

1. **不影響市場**。模擬委託不會改變之後的真實行情：真實的成交價、成交量、五檔與試撮都照資料
   重播。模擬委託只能拿到「在這個假設下確定拿得到」的量，超出的部分不成交。
2. **只用已揭示的資訊**。交易所只揭示最佳五檔的合計量，沒有逐筆委託與排隊順序。看不到的部分一律
   取保守值（成交較少、價格較差），並在成交紀錄標明成交依據。
3. **決定性**。相同的 marketdata identity、設定與策略，產生完全相同的委託事件與成交。
4. **整數運算**。價格是 1e-4 元的整數，數量是股，比較與比例都用整數或有理數，不使用浮點數。

模擬委託之間不互相撮合；同一策略的買單與賣單各自對真實行情撮合。

## 2. 名詞

| 名詞 | 定義 |
| --- | --- |
| book | 一個商品 `(venue, symbol)` 在一個 board 上的委託簿。`REG`（F6、F17）與 `ODD`（F23）是兩本獨立的 book |
| 股 | 所有數量的單位。`REG` 資料的張數乘以 `instruments.shares_per_lot` |
| 揭示列 | `books` 中非試撮、非暫緩撮合、帶五檔的列。只有揭示列會更新「目前的五檔」 |
| 試撮列 | `books.is_indicative`。五檔是試算撮合後的剩餘量，不是真實掛單量 |
| 暫緩列 | `books.delay_state ≠ 0`，沒有五檔 |
| 撮合列 | `phase ≠ CONTINUOUS` 的揭示列：一次集合競價的結果，可能有成交（`has_trade`）也可能沒有 |
| 成交 | `trades` 的一列：一筆主動委託在一個價位的成交 |
| 對手方 | 買單的對手方是賣方五檔，賣單反之 |
| 較優／較差 | 買單價格高為優，賣單價格低為優 |

以下規則以買單描述，賣單對稱。

## 3. 時間與延遲

三個延遲都是設定值（微秒，≥ 0，整個 run 固定）：

| 參數 | 意義 |
| --- | --- |
| `latency.market_data` | 行情訊息在 `observed_time + latency.market_data` 送達策略 |
| `latency.order` | 策略在時刻 `t` 送出的新單、改單、刪單，在 `t + latency.order` 到達交易所 |
| `latency.report` | 交易所在時刻 `t` 產生的回報（接受、拒絕、成交、刪單、失效），在 `t + latency.report` 送達策略 |

- 委託在到達時刻 `t_a` 才存在於交易所。處理順序上，它排在所有 `observed_time ≤ t_a` 的行情訊息
  之後；因此到達時看到的五檔，是交易所在 `t_a` 當下已揭示的五檔，不是策略下決定時看到的。
- 委託只會被到達之後的訊息撮合。
- 完整的事件全序見[回放規格](replay.md)。

## 4. Book 的交易模式

### 4.1 撮合方式

每本 book 每天有一個固定的撮合方式：

| 條件 | 撮合方式 |
| --- | --- |
| `ODD` board | 分盤（每輪集合競價） |
| `REG`，`instruments.match_interval_s > 0` | 分盤 |
| `REG`，`match_interval_s == 0` | 逐筆 |
| `REG`，`match_interval_s` 為 null | 當天這本 book 在開盤撮合列之後、13:25 之前有非 `CONTINUOUS` 的列，而且整天沒有 `CONTINUOUS` 的列 → 分盤；否則逐筆 |

最後一列用到當天的全部資料。撮合方式是交易所事前公告的屬性，不是行情結果，所以不算偷看未來；
`match_interval_s` 缺值的期間見 [marketdata](marketdata.md)。

### 4.2 模式

模式由資料與時鐘決定，依序判斷，命中即停：

| # | 條件 | 模式 |
| --- | --- | --- |
| 1 | 還沒出現開盤撮合列（`phase = OPEN_AUCTION` 的撮合列） | `Collecting(Open)` |
| 2 | 已出現收盤撮合列（`phase = CLOSE_AUCTION` 的撮合列） | `Closed` |
| 3 | 撮合方式為分盤 | `Collecting(Periodic)` |
| 4 | 時刻 ≥ 13:25:00 | `Collecting(Close)` |
| 5 | 出現過暫緩列，之後還沒有撮合列 | `Collecting(Volatility)` |
| 6 | 其他 | `Continuous` |

- 每本 book 每天恰有一列開盤撮合列與一列收盤撮合列，有沒有成交都有（2022-06-15、2026-10-15 各 feed
  實測，含 S3 期間）。延後開盤、延後收盤不需要另外判斷：撮合列出現之前就是收單期間。
- `Collecting(*)` 的行為完全相同（第 7 節），括號內只是原因。
- 分盤 book 的暫緩列不改變模式（本來就在收單）。
- 資料在收盤撮合列之前結束時，當天結束即視為 `Closed`。

### 4.3 收單時間

到達時刻不在收單時間內的新單、改單一律拒絕（`MarketClosed`）；刪單不受限。

| board | 收單時間（台北時間） | 生效期間 |
| --- | --- | --- |
| `REG` | 08:30:00 ≤ t < 13:30:00 | 全部資料期間 |
| `REG`，延後收盤 | 另加 13:31:00 ≤ t < 13:33:00，條件是模式仍為 `Collecting(Close)` | 同上 |
| `ODD` | 09:00:00 ≤ t < 13:30:00 | 至 2026-12-06 |
| `ODD` | 08:30:00 ≤ t < 13:30:00 | 2026-12-07 起 |

出處：研究 §1.1、§2.6、§4.1、§4.2。模式為 `Closed` 時一律拒絕。

## 5. 委託

### 5.1 種類

| 欄位 | 值 |
| --- | --- |
| 買賣別 | 買、賣 |
| 價格別 | 限價、市價 |
| 有效期別 | `ROD`（當日有效）、`IOC`、`FOK` |
| board | `REG`、`ODD` |
| 數量 | 股 |

交易類別（現股、融資、融券、當沖）屬於帳務，見[帳務規格](accounting.md)。委託只在當天有效；
沒有跨日委託。

### 5.2 到達時的檢查

依序檢查，第一個不符即拒絕。除了第 8 項，其餘都是交易所規則（研究 §1.3、§1.5、§4.4、§6）。

| # | 檢查 | 拒絕原因 |
| --- | --- | --- |
| 1 | 當天 `instruments` 有這個商品，這個 board 當天有資料，幣別為 `TWD`，商品類別受支援（5.3） | `UnknownInstrument`／`UnsupportedInstrument` |
| 2 | 在收單時間內，模式不是 `Closed` | `MarketClosed` |
| 3 | `REG`：數量是 `shares_per_lot` 的正整數倍，且不超過 499 張。`ODD`：1 ≤ 數量 ≤ `shares_per_lot − 1` | `InvalidQuantity` |
| 4 | 限價單：價格符合升降單位（5.3） | `InvalidTick` |
| 5 | 限價單：`limit_down ≤ 價格 ≤ limit_up`。漲跌停為 null 或無漲跌幅（5.4）時略過 | `PriceOutOfLimit` |
| 6 | 委託種類在目前模式下允許（下表） | `OrderTypeNotAllowed` |
| 7 | 市價單：商品有漲跌幅限制（5.4） | `OrderTypeNotAllowed` |
| 8 | 帳務的事前檢查通過（資金、庫存、信用資格等，見帳務規格） | 帳務的拒絕原因 |

| 模式 | 限價 `ROD` | 限價 `IOC`／`FOK` | 市價 `ROD`／`IOC`／`FOK` |
| --- | --- | --- | --- |
| `Continuous` | ✅ | ✅ | ✅ |
| `Collecting(*)` | ✅ | ❌ | ❌ |

`ODD` 與分盤 book 永遠是 `Collecting`，所以只接受限價 `ROD`。

### 5.3 商品類別與升降單位

商品類別由 `instruments.instrument_type` 與代號決定。`OTHER` 是混合類別，必須用代號再分：

| 商品類別 | 判定 | 升降單位表 |
| --- | --- | --- |
| 股票 | `STOCK`、`TDR`；`OTHER` 且代號為 4 位數字加英文字尾（特別股，如 `2881A`、`2887Z1`）；`OTHER`、TWSE、`91` 開頭 6 位數字（TDR） | 股票 |
| ETF 類 | `ETF`、`ETN`、`REIT`；`OTHER` 且代號為 `00` 開頭 6 位數字（ETF）；`OTHER` 且代號為 `02` 開頭加英文字尾（ETN） | ETF |
| 權證 | `WARRANT_C`、`WARRANT_P` | 權證 |
| 轉（交）換公司債 | `OTHER`、TPEX、5 或 6 位數字且不屬於上面各列 | 公司債 |
| 不支援 | 其他 | — |

| 表 | 價格區間 → 升降單位（元） |
| --- | --- |
| 股票 | <10 → 0.01；10–<50 → 0.05；50–<100 → 0.1；100–<500 → 0.5；500–<1000 → 1；≥1000 → 5 |
| ETF | <50 → 0.01；≥50 → 0.05 |
| 權證 | <5 → 0.01；5–<10 → 0.05；10–<50 → 0.1；50–<100 → 0.5；100–<500 → 1；≥500 → 5 |
| 公司債 | <150 → 0.05；150–<1000 → 1；≥1000 → 5 |

- 股票、ETF、權證三張表來自交易所（研究 §6）。各類別套用哪張表，以 2026-10-08 全部六個 feed 的
  委託簿價格反推驗證：`ETN`、`REIT`、6 位數 ETF 符合 ETF 表；特別股、TDR 符合股票表；公司債表的
  前兩個區間由資料確認，≥1000 區間沒有樣本，取公開資料的通行值，**未經官方來源確認**。
- 區間以委託價本身所在的區間為準。

### 5.4 漲跌停

漲跌停價一律讀當天 `instruments.limit_up`／`limit_down`，不自行計算（研究 §6）。

- `limit_up ≥ 9995` 且 `limit_down ≤ 0.01` 視為無漲跌幅：略過價格範圍檢查，不接受市價單。
- 任一為 null（沒有 Format 1 的日子的部分商品）：略過價格範圍檢查，不接受市價單，並記錄診斷
  `limit_unknown`。

### 5.5 改單與刪單

改單、刪單在 `t + latency.order` 到達；到達時委託已完全成交或已失效則拒絕（`TooLate`）。

| 動作 | 規則 |
| --- | --- |
| 刪單 | 剩餘量取消 |
| 減量 | 剩餘量減少，排隊位置不變。不可增量 |
| 改價 | 只有 `REG` 的限價 `ROD` 可以。等於在同一時刻刪單再下新單：重新做 5.2 的檢查，排隊位置重算 |

`ODD` 不可改價（研究 §1.6、§4.4）。

## 6. 逐筆撮合（`Continuous`）

### 6.1 狀態

每本 book、每一側、每個價位記錄 `consumed`：模擬委託已經從這個價位吃掉、而真實行情還沒反映的量。

- 可用量 = 揭示量 − `consumed`。
- 每次揭示列之後：`consumed = min(consumed, 揭示量)`；價位不在揭示的五檔內時，若它比第五檔差
  （看不到）則保留，否則（已消失）歸零。

每筆掛在簿上的模擬委託記錄 `queue_ahead`：同價位、排在它前面的真實委託量。

### 6.2 到達時：主動成交

買單到達時，依賣方五檔由優至劣：

1. 只考慮價格 ≤ 委託價（市價單不限）且在價格穩定範圍內（6.6）的價位。
2. 每個價位成交 `min(剩餘量, 可用量)`，**成交價是該價位的價格**；該價位的 `consumed` 增加同樣的量。
3. `FOK`：先算出可成交的總量，不足全部數量則整筆取消，不成交。
4. 處理完之後的剩餘量：
   - 限價 `ROD`：掛在委託價上（6.3）。
   - `IOC`：取消。
   - 市價 `ROD`：取消（見 6.7）。

### 6.3 掛單時：排隊位置

掛上時設定 `queue_ahead`：

| 委託價相對於同側五檔 | `queue_ahead` |
| --- | --- |
| 在揭示的價位上 | 該價位的揭示量；若是最佳一檔，再加上同側的市價委託量（`*_mkt_qty`） |
| 優於最佳一檔，或在兩個揭示價位之間，或揭示檔數少於 5 檔而沒有這個價位 | 0 |
| 差於第五檔（看不到） | 未知；之後這個價位第一次出現在揭示列時，設為當時的揭示量 |

同一策略在同價位有多筆委託時，後到的排在先到的後面。

之後每一列揭示列：

- 揭示量增加：不變（新委託排在我們後面）。
- 揭示量減少而沒有成交：**假設刪掉的都是排在我們後面的委託**，`queue_ahead` 不變。
- 只有揭示量小於 `queue_ahead` 時，才下修為揭示量；價位從五檔內消失（不是被擠到第五檔之外）時
  歸零。

### 6.4 被動成交

先判斷每筆真實成交的主動方：以這組成交開始之前最後一次揭示的五檔為準，成交價 ≥ 賣一 → 買方主動；
成交價 ≤ 買一 → 賣方主動；否則未知。同一筆主動委託連續吃多檔的各筆成交（含只在 `trades` 的中間
成交）共用同一份成交前五檔。主動方未知的成交不產生模擬成交，也不改變 `queue_ahead`，並計入診斷
`aggressor_unknown`（實測逐筆交易中約 0.01%）。

賣方主動、成交價 `p`、成交量 `q` 的真實成交，對掛著的模擬買單依「價格較優者先、同價先到者先」處理，
`B` 初值為 `q`：

| 委託價 `P` | 處理 | 成交依據 |
| --- | --- | --- |
| `P > p`（成交穿過委託價） | `queue_ahead = 0`；成交 `min(剩餘量, B)` | `PassiveThrough` |
| `P = p` | `a = min(queue_ahead, q)`，`queue_ahead −= a`；成交 `min(剩餘量, max(0, B − a))` | `PassiveQueue` |
| `P < p` | 不處理 | |

每筆成交後 `B` 減去成交量。**成交價一律是委託價 `P`**（被動方的價格）。

理由：真實成交穿過委託價，表示委託價上已經沒有排在前面的真實委託，而且主動方的量會先碰到我們；
這筆真實成交的量就是在不影響市場的前提下我們最多能拿到的量。

### 6.5 掛單後對手方出現可成交的量

掛著的模擬買單，委託價 `P`。任何揭示列之後，若賣方有價格 ≤ `P`、在價格穩定範圍內、可用量 > 0 的
價位，由優至劣成交 `min(剩餘量, 可用量)`，並增加該價位的 `consumed`。

**成交價一律是委託價 `P`**（成交依據 `CrossedPassive`）：真實市場中，這些賣單進場時我們已經掛在
簿上，是被動方。少數情況下（例如原本看不到的第六檔補進來）真實成交價會比 `P` 好，這裡取保守值。

買方主動的真實成交不直接產生模擬買單的成交；它造成的揭示量減少由 6.1 的 `consumed` 規則處理。

### 6.6 價格穩定範圍

真實的瞬間價格穩定措施（研究 §3）由資料重播。模擬委託不能觸發暫緩撮合，但它的主動成交不得超出
同一個範圍：

- 適用：`REG` 逐筆 book，開盤撮合列之後到 13:25:00 之前。
- 不適用：權證、`instruments.ref_price` < 1 元、無漲跌幅或漲跌停未知的商品。
- 參考價 `r`（時間一律用 `exch_ts`）：
  1. 開盤撮合列起 5 分鐘內：開盤成交價；開盤沒有成交時為 `ref_price`。
  2. 暫緩撮合結束的撮合列起 5 分鐘內：該次成交價；該次沒有成交時用第 3 點。
  3. 其他：往前 5 分鐘內真實成交的成交量加權平均價（有理數，不捨入）；5 分鐘內沒有成交時為最近
     一次成交價；當天沒有成交時為 `ref_price`。
- 買進成交價 `p` 必須滿足 `p × 1000 ≤ r × 1035`；賣出必須滿足 `p × 1000 ≥ r × 965`。

超出範圍的價位視為不可用：限價 `ROD` 的剩餘量照常掛著；`IOC` 與市價單的剩餘量取消；`FOK` 把
範圍外的量當成不存在。委託因此少成交時，在委託事件記錄 `price_band_limited`。

交易所是否把上下限先取到升降單位、等號是否算超逾，官方沒有明文（研究 §3.1）；這裡採用「嚴格超過
才算超逾、不取整」。實作時以真實成交驗證：真實的逐筆成交不應落在這個範圍之外。

### 6.7 市價單

市價單只在到達時依 6.2 成交，價位範圍是漲跌停以內、價格穩定範圍以內的揭示五檔。剩餘量一律取消
（`MarketRemainderCancelled`），包括 `ROD`。

與真實規則的差異：真實的市價 `ROD` 餘量會留在簿上（研究 §1.4）。但那只發生在對手方全部吃完之後，
而第六檔以後看不到，無法判斷；取消是保守的處理。

## 7. 集合競價（`Collecting`）

適用於開盤、收盤、暫緩撮合結束、盤中零股每一輪、分盤股票每一輪。成交價決定原則見研究 §2.1。

### 7.1 收單期間

- 只接受限價 `ROD`。委託到達後不會立即成交，等下一列撮合列。
- 試撮列與暫緩列不影響模擬委託：試撮的五檔是試算後的剩餘量，不用來更新 `consumed` 或
  `queue_ahead`。
- 進入收單期間時已經掛在簿上的委託原樣保留。

### 7.2 撮合列

撮合列的成交價 `p*`、成交量 `q*`（沒有成交時 `q* = 0`），以及撮合後的五檔。到達時刻早於撮合列
時刻的模擬委託參加這次撮合。先以撮合後的五檔依 6.1 更新 `consumed`，再依序做下面三步。

**第一步：有成交時，價格優於 `p*` 的委託。**
交易所規則保證高於成交價的買單全部成交。在不影響市場的前提下，成交價仍是 `p*`，我們能拿到的量
有兩個來源：

- `opp_left`：撮合後賣方在 `p*` 剩下的可用量（真實賣單沒賣完的部分）。
- `displace`：`q*`（原本成交的真實買單，價格優先權不如我們）。

依「價格較優者先、同價先到者先」，每筆成交 `min(剩餘量, opp_left + displace 的餘額)`，先扣
`opp_left` 再扣 `displace`。成交價 `p*`，成交依據 `AuctionBetter`。從 `opp_left` 拿的量計入賣方
`p*` 的 `consumed`。

超過 `opp_left + q*` 的量在真實市場必定會改變成交價，不在假設的適用範圍內，這一步不成交。

**第二步：有成交時，價格等於 `p*` 的委託。**
依先到者先，每筆成交 `min(剩餘量, opp_left 的餘額)`，成交價 `p*`，成交依據 `AuctionOpposite`。

對手方在 `p*` 有剩，表示同側在 `p*` 的委託全部成交，我們也會成交。對手方沒有剩時，同價位的成交
依時間優先分配（開盤前的委託是電腦隨機排序），從揭示資料無法判斷，預設不成交。設定
`matching.auction_marginal = "queue"` 時改用樂觀的估計：把 `q*` 當成同價位的成交量，額外成交
`min(剩餘量, max(0, q* − queue_ahead) − 同價位先到的模擬委託在這一步已成交的量)`，並把
`queue_ahead` 減去 `min(queue_ahead, q*)`（成交依據 `AuctionQueue`）；`queue_ahead` 未知時視為
無限大。兩種設定分別是下限與上限，可以各跑一次來夾出範圍。

**第三步：剩餘委託與撮合後五檔的交叉。**
前兩步之後仍有剩餘、而且委託價 ≥ 撮合後賣一的買單（包括 `q* = 0` 的情形），依優先順序逐筆對
撮合後賣方的可用量做一次集合競價：

- 可成交量 `F = min(剩餘量, 價格 ≤ P 的各檔可用量合計)`，由優至劣取用，取到的最後一檔價格為 `a_k`。
- 成交價（單一價格，依成交價決定原則）：
  - `F` 小於剩餘量（看得到的賣單全部吃完，我們沒有全部成交）：`P`。
  - 全部成交，而且 `a_k` 那一檔沒有吃完：`a_k`。
  - 全部成交，而且 `a_k` 那一檔剛好吃完：在 `[a_k, hi]` 中最接近參考價者，其中 `hi` 是「下一檔揭示
    的賣價減一個升降單位」與 `P` 的較小者（沒有下一檔時為 `P`），參考價是這本 book 當天最近一次
    成交價，當天沒有成交時為 `ref_price`。
- 取用的量計入各檔的 `consumed`。成交依據 `AuctionResidual`。

這一步處理「對手方的量一直掛在那裡，但因為真實市場沒有人去吃，所以資料中沒有成交」的情形；盤中
零股的主動買賣主要靠這一步成交。

### 7.3 撮合之後

- 還有剩餘的委託留在簿上，`queue_ahead` 重設為撮合後五檔在委託價上的揭示量（規則同 6.3 的表）。
  也就是：撮合後還留在同價位的真實委託一律視為排在我們前面。這對開盤前的隨機排序是保守值，對
  其他收單期間也是。撮合前已經有 `queue_ahead` 的委託則取 `min(原值, 揭示量)`。
- 模式變成 `Continuous` 時，立即套用 6.5。
- 收盤撮合列之後，所有剩餘委託失效（`Expired`）。

## 10. 已知限制

模擬器不處理、或以保守方式處理的情形。每一項都偏向少成交或較差的價格，除非另外說明。

| 項目 | 處理 |
| --- | --- |
| 大單 | 不影響市場的假設只對相對於市場成交量很小的委託成立。規則已限制每筆成交不超過真實出現過的量，但連續大量吃單仍會高估可得的流動性 |
| 第六檔以後 | 看不到。委託價穿過五檔時，只對看得到的量成交 |
| 排隊位置 | 以到達時的揭示量估計；刪單一律假設在後面。漲跌停鎖死時，成交封包中漲跌停價那一檔的量可能沒有更新（marketdata `sources.md` §7），`queue_ahead` 因此偏大 |
| 集合競價的同價位分配 | 預設不成交（7.2 第二步） |
| 模擬委託觸發暫緩撮合 | 不模擬；改以價格穩定範圍限制主動成交（6.6） |
| 市價 `ROD` 的餘量 | 取消（6.7） |
| 盤中暫停交易 | 不模擬。暫停期間沒有真實訊息，委託不會成交；恢復時的集合競價若以撮合列呈現，依第 7 節處理 |
| 封包遺失（F17、F23 與部分日期） | 遺失的成交不會產生模擬成交，也不會扣減 `queue_ahead`；之後的揭示列照常更新狀態。受影響的日子見 marketdata `qc/` |
| 2022-01-03 → 2024-03-29（S3） | 沒有中間成交標記：每筆成交都帶五檔，規則不變。沒有 `match_interval_s`：撮合方式由資料推定（4.1） |
| 平盤下放空、當沖、信用資格、預收款券 | 屬於帳務的事前檢查，見帳務規格 |
| 盤後定價、盤後零股、鉅額交易 | 不在資料內，不支援 |
| 外幣計價商品 | 不支援 |

## 11. 驗證

實作必須以真實資料驗證下列性質，測試列在[驗證](../development/validation.md)：

- 每本 book 每天恰有一列開盤撮合列與一列收盤撮合列。
- 逐筆 book 的真實成交都落在 6.6 的範圍內。
- 把一筆真實出現過的成交「重下一次」（同價、同量、到達時刻略早於該成交），結果符合 6.2–6.4。
- 相同輸入重跑，輸出位元組相同。
