# 帳務規格

`osmium-ledger` 的精確行為。法規出處、生效日期與信心等級記錄在
[現股帳務規則研究](../design/research/cash-accounting-rules.md)（以下寫作「現股 §n」）與
[信用交易規則研究](../design/research/margin-rules.md)（「信用 §n」）；本頁只寫帳務怎麼算。

狀態：規格已定案，實作進行中（見[架構的遷移狀態](../design/architecture.md#遷移狀態)）。

## 1. 原則

1. **現金帳是唯一的事實**。所有金額是整數新臺幣元；價格是 1e-4 元的整數；數量是股；比率是十進位
   有理數。乘法之後只在本頁指定的位置捨入一次。沒有浮點數。
2. **每一筆分錄都可追溯**到一筆模擬成交、一個公司行動、或一條本頁的規則。
3. **不猜測**。資料缺少必要的事實時（例如減資比例），預設讓 run 失敗並指出缺什麼；使用者可以用
   設定補上事實，或明確選擇近似。用到近似的分錄都帶 `approx` 標記。
4. **券商自訂的項目是參數**（手續費折扣、最低手續費、捨入、利率等），預設值是法規的標準值或業界
   通行值，並在第 15 節列出。
5. 只支援新臺幣計價的商品，單一帳戶。

總損益恆等於「期末權益 − 期初權益 − 外部出入金」，與成本計算方法無關。

## 2. 帳戶狀態

| 項目 | 內容 |
| --- | --- |
| `cash` | 已交割的現金 |
| 待交割款 | 每個交割日一個淨額（應收為正、應付為負） |
| 現股部位 | 每個商品一串批次（lot）：股數、總成本（元）、取得日 |
| 融資部位 | 每個批次：股數、成交價款、融資金額、自備款、開倉交割日 |
| 融券部位 | 每個批次：股數、成交價款、保證金、擔保價款、開倉交割日 |
| 應收股利、待配發股票 | 公司行動產生，於發放日入帳 |
| 追繳紀錄 | 第 12 節 |

`ODD` 與 `REG` 的成交進同一個部位（單位都是股）。

## 3. 一天的流程

以交易日 `T` 為例。交割日曆見第 7 節。

1. **開盤前**（當天第一則行情之前），依序：
   1. 交割：把交割日為今天的待交割款併入 `cash`。
   2. 公司行動：除權息日為今天的事件，依前一交易日收盤後的部位計算權益（第 13 節）；發放日為
      今天的現金與股票入帳。
   3. 信用交易：到期、強制回補、追繳處分所產生的強制委託在這時送出（第 10、12 節）。
2. **盤中**：每筆模擬成交即時更新部位數量與暫估的現金影響，供策略查詢與事前檢查使用。暫估值
   用同一套公式對「到目前為止的成交」計算。
3. **日結**（當天行情結束後），依序：當沖與資券相抵配對（第 8、11 節）→ 手續費與證交稅（第 5、
   6 節）→ 批次與已實現損益（第 14 節）→ 產生交割日 `S(T)` 的待交割款 → 以官方收盤價評價 →
   維持率與追繳（第 12 節）→ 檢查未回補的先賣後買與融券回補期限。

只辦理交割、不交易的日子只做第 1.1 步。日結的結果才是正式分錄；盤中暫估值不寫入輸出。

## 4. 交易類別與事前檢查

委託帶一個交易類別：

| 類別 | 說明 | 可用的 board |
| --- | --- | --- |
| `Cash` | 現股買進、現股賣出 | `REG`、`ODD` |
| `CashSellFirst` | 現股當沖先賣（賣出時沒有庫存） | `REG` |
| `MarginBuy`／`MarginSell` | 融資買進／融資賣出（償還） | `REG` |
| `ShortSell`／`ShortCover` | 融券賣出／融券買進（回補） | `REG` |

委託到達交易所時（[撮合規格](matching.md) 5.2 第 8 項）依序檢查，不符即拒絕：

| # | 檢查 | 拒絕原因 |
| --- | --- | --- |
| 1 | 類別與 board、商品相容：`ODD` 只能 `Cash`；信用交易限得為融資融券的商品（第 9 節） | `KindNotAllowed` |
| 2 | 可賣數量。`Cash` 賣出：庫存（含前幾天買進尚未交割者）＋今天已成交的現股買進（須可當沖，第 8 節）− 今天已成交與掛單中的現股賣出。`MarginSell`／`ShortCover`：對應的融資／融券部位 − 掛單中的量 | `InsufficientPosition` |
| 3 | `CashSellFirst`：可先賣後買當沖（第 8 節） | `DayTradeNotAllowed` |
| 4 | `ShortSell`：不在停止融券期間；平盤下限制（第 10 節） | `ShortNotAllowed`／`ShortPriceRestricted` |
| 5 | 處置期間的預收款券（第 4.1 節） | `PrepaymentRequired` |
| 6 | 資金（第 7.3 節） | `InsufficientCash` |
| 7 | 單日買賣額度 `account.daily_limit`（買賣成交與掛單金額合計；0 表示不限） | `DailyLimitExceeded` |

被接受的委託保留對應的資金或部位，成交、取消或失效時釋放。

### 4.1 處置期間

商品在 marketdata `events` 的 `disposition` 期間內（`start_date` 至 `end_date`，含）：

- 不得當沖（`CashSellFirst` 拒絕；同日現股買賣不配對）。
- `disposition.prepay = "all"`（預設）：買進必須有足額的已交割現金，賣出必須是已交割的庫存。
  交易所的規定依處置次數與數量而不同（現股 §3.5、信用 §1），資料中沒有結構化的欄位，這裡取最嚴
  的一種。設為 `"none"` 則不檢查。

## 5. 手續費

法規只規定手續費由券商訂定、超過 0.1425% 須事前通知、得訂每筆委託的最低費用（現股 §1）。

```text
計費單位   = 一筆委託在一天內的全部成交（fee.aggregation = "order"）
成交金額   = Σ 各筆成交的價金（零股的價金見 7.4）
手續費     = max(最低費用, round(成交金額 × fee.rate × fee.discount))
```

- 買賣都收。成交金額為 0 不收。
- `round` 由 `fee.rounding` 決定（`floor` 預設、`half_up`、`ceil`）。
- 最低費用：`REG` 為 `fee.min_regular`（預設 20），`ODD` 為 `fee.min_odd`（預設 1）。
- 手續費在日結時計算，併入當天的待交割款。
- 一筆手續費涵蓋多筆成交時，依價金比例分攤到各筆成交（最大餘數法，整數加總等於實收），用於成本
  與損益。

事後退佣（月退、週退）不模擬；折扣一律在成交時計入。

## 6. 證券交易稅

只對賣方課徵（現股 §2）。稅率依稅別與日期：

| 稅別 | 判定（商品類別見撮合規格 5.3） | 稅率 |
| --- | --- | --- |
| 股票 | `STOCK`、特別股 | 0.3%；現股當沖配對的部分 0.15%（2017-04-28 → 2027-12-31） |
| TDR | `TDR`、`91` 開頭 6 位數字 | 0.1% |
| ETF | ETF 類中的 ETF，不屬於下一列者 | 0.1% |
| 債券 ETF | ETF 且代號字尾為 `B` | 0（2017-01-01 → 2026-12-31），之後 0.1% |
| ETN | ETF 類中的 ETN | 0.1% |
| REIT | `REIT` | 0 |
| 權證 | `WARRANT_C`、`WARRANT_P` | 0.1% |
| 轉（交）換公司債 | 公司債類 | 0（2010-01-01 → 2026-12-31），之後 0.1% |

```text
計稅單位 = 一筆賣出委託在一天內的全部成交
稅額     = floor(當沖配對部分的價金 × 當沖稅率) + floor(其餘部分的價金 × 一般稅率)
```

- 當沖稅率只適用股票的現股當沖；ETF、TDR 當沖與資券相抵都用一般稅率。
- 稅額在日結時計算，併入當天的待交割款。
- 到期日是現行法律的規定；修法延長時更新本表與 `osmium-ledger` 的版本。主動式債券 ETF（字尾
  `D`）現行課 0.1%。
- 計稅單位與捨入方式法規沒有明文（現股 §2.4），這裡採用業界常見的做法，尚未用實際對帳單校驗。

## 7. 交割

### 7.1 交割日

- 交易日：marketdata `qc/calendar` 中 `twse_open` 為 true 的日子。
- 交割日 = 交易日 ∪ 只辦理交割的日子。後者不在 marketdata 中，內建於 `osmium-ledger`：
  2022-01-27、2022-01-28、2023-01-18、2023-01-19、2024-02-06、2024-02-07、2025-01-23、2025-01-24、
  2026-02-12、2026-02-13（現股 §3.3）。
- `S(T)` = `T` 之後的第 2 個交割日。
- 颱風等臨時休市日不是交割日，自然順延。
- 需要的日期超出日曆範圍時 run 失敗，不外推。

### 7.2 待交割款

同一個交割日的所有款項合併成一個淨額（現股 §3.2），在該交割日開盤前併入 `cash`：

| 交易 | 計入 `S(T)` 的金額 |
| --- | --- |
| 現股買進 | −(價金 + 手續費) |
| 現股賣出 | +(價金 − 手續費 − 證交稅) |
| 融資買進 | −(價金 + 手續費 − 融資金額) |
| 融資賣出 | +(價金 − 手續費 − 證交稅 − 融資金額 − 融資利息) |
| 融券賣出 | −保證金 |
| 融券買進 | +(擔保價款 + 保證金 + 利息 − 價金 − 手續費) |

當沖與資券相抵不需要另外的交割規則：兩腿計入同一個交割日，淨額就是差價。

證券在成交當下計入部位（賣出前一天買進的股票是允許的，現股 §3.4），不另外追蹤券的交割。

### 7.3 資金檢查

`account.cash_check`：

| 值 | 行為 |
| --- | --- |
| `"at_order"`（預設） | 委託到達時，對這筆委託的交割日 `S` 及之後每一個已有待交割款的日子 `d`，要求 `cash + Σ(交割日 ≤ d 的待交割款) − 掛單保留的金額 ≥ 0`。當天賣出的應收款可以支應當天的買進 |
| `"at_settlement"` | 委託時不檢查。交割時 `cash` 變成負數即記錄 `SettlementShortfall`，run 失敗 |
| `"none"` | 不檢查，`cash` 可以為負 |

掛單保留的金額：買進為 `委託價 × 剩餘量 + 暫估手續費`（市價單用漲停價）；融資買進扣除暫估的融資
金額；融券賣出為暫估的保證金。

實際上券商下單時通常不檢查現金，只管單日額度，違約發生在交割日。`"at_order"` 是回測用的保守
預設，確保結果不含無法交割的交易；做當沖而不想準備全額資金時用 `"at_settlement"`。

### 7.4 零股的價金

`ODD` 成交的價金可能不是整數元。依交易所的規劃（現股 §7），同一筆委託、同一個成交價的成交合併後，
元以下捨去：`價金 = floor(價格 × 該價位的成交股數合計)`。買賣雙方相同。手續費與證交稅以捨去後的
價金計算。`REG` 的價金一定是整數。

## 8. 現股當沖

法規見現股 §4。

### 8.1 資格

`account.daytrade_enabled`（預設 true）為 false 時，同日買賣不配對，`CashSellFirst` 一律拒絕。

| 當天 `instruments.f1_daytrade_flag` | 先買後賣 | 先賣後買 |
| --- | --- | --- |
| `A` | 可 | 可 |
| `B` | 可 | 不可 |
| null，而且當天的來源是 `F1` | 不可 | 不可 |

當天的 `instruments` 不是來自 `F1`（2024-03-29 以前、2026-10-13 起）時沒有這個旗標，改用近似並標記
`approx`：商品類別為股票或 ETF 類（不含 ETN、REIT），而且不在 `events.disposition` 期間 → 可先買
後賣；另外不在 `events.daytrade_suspended` 期間 → 可先賣後買。這個近似會高估（無法排除非信用交易
標的與全額交割股）。

另外的限制：只有 `REG`；處置期間不可；權證、ETN、REIT、公司債不可。

### 8.2 配對

日結時，對每個可當沖的商品，把當天 `REG` 的 `Cash`／`CashSellFirst` 成交依時間順序處理，維護「尚未
配對的買進量」與「尚未配對的賣出量」：

- 一筆賣出成交：先與尚未配對的買進量配對（先買後賣）；剩下的部分，若可先賣後買則記為尚未配對的
  賣出量。
- 一筆買進成交：若可先賣後買，先與尚未配對的賣出量配對；剩下的記為尚未配對的買進量。

配對的部分是當沖：股票的賣出價金適用當沖稅率，損益直接由這一對買賣算出，不動用庫存批次。
旗標為 `A` 時，配對量等於 `min(當天買進合計, 當天賣出合計)`。

沒有配對的買進成為新的庫存批次；沒有配對的賣出從庫存批次扣（第 14 節）。

### 8.3 未回補的先賣後買

日結時，賣出超過「庫存＋當天買進」的部分是沒有回補的先賣後買。`daytrade.uncovered`：

| 值 | 行為 |
| --- | --- |
| `"error"`（預設） | run 失敗。策略必須保證收盤前回補 |
| `"force_cover"` | 依法規由券商在次一交易日強制買回（現股 §4.1）：開盤前送出強制買進委託，限價為漲停價，並收取借券費 `floor(未回補股數 × T 日收盤價 × daytrade.borrow_fee_rate)`（預設 0.07，法規上限）。強制委託連續 6 個交易日無法全部成交時 run 失敗 |

實際的強制買回價格與費用由券商決定，`"force_cover"` 的結果帶 `approx` 標記。

## 9. 融資

法規見信用 §1、§2。

### 9.1 資格

零股、權證、ETN、特別股、REIT、公司債不得融資融券。其餘商品需要「得為融資融券」的每日名單、
停資停券註記與個股成數調整，這些不在 marketdata 中。`credit.eligibility`：

| 值 | 行為 |
| --- | --- |
| `"marketdata_approx"`（預設） | 前一交易日 `daily_ext.margin_limit > 0` → 可融資；`short_limit > 0` 且不在 `events.short_suspended` 期間 → 可融券。成數用全市場的一般值。結果帶 `approx` 標記 |
| `"none"` | 一律拒絕信用交易 |

`events.disposition` 期間，融資比率視為 0（拒絕融資買進）、融券保證金成數加 10 個百分點且不低於
100%。法規只對第二次以上的處置這樣規定，資料無法區分次數，取較嚴者。

### 9.2 開倉

```text
融資金額 = floor(一筆委託當天的成交價款 × 融資比率 ÷ 1000) × 1000
自備款   = 成交價款 − 融資金額
```

融資比率預設 `credit.margin_loan_ratio = 0.60`（上市、上櫃相同）。一筆委託一天的成交成為一個融資
批次。計算單位法規沒有明文（信用 §10 第 4 點）。

### 9.3 利息與償還

- 利息 = `round(融資金額 × credit.margin_interest_rate × 日數 ÷ 365)`，日數是開倉交割日到清償日的
  日曆天數（開倉交割日算、清償日不算）。賣出償還的清償日是賣出成交的交割日。
- `round` 由 `credit.interest_rounding` 決定（預設 `half_up`）。
- 融資賣出依先進先出償還批次。部分償還時，融資金額依股數比例分攤：
  `floor(批次融資金額 × 償還股數 ÷ 批次股數)`，最後一次償還取餘額。
- 現金償還不支援。
- 期限：開倉日起 `credit.term_months`（預設 6）個月，可展延 `credit.max_extensions`（預設 2）次。
  到期未了結的批次，次一交易日開盤前送出強制委託（規則同 12.4）。

融資部位的股利歸客戶，處理方式與現股相同（第 13 節）。

## 10. 融券

法規見信用 §3、§6。

### 10.1 開倉

```text
保證金   = ceil(成交價款 × 保證金成數 ÷ 100) × 100
融券手續費 = floor(成交價款 × credit.short_fee_rate)
擔保價款 = 成交價款 − 證交稅 − 融券手續費 − 手續費
```

保證金成數取成交日適用的最低成數（新成數不追溯既有部位）：

| 成交日自 | 最低融券保證金成數 |
| --- | --- |
| （資料起點） | 90% |
| 2022-10-03 | 100% |
| 2022-10-12 | 120% |
| 2023-02-24 | 90% |
| 2025-04-07 | 130% |
| 2025-05-26 | 90% |
| 2026-11-09 | 130% |

每一列適用到下一列的生效日之前。

`credit.short_margin_ratio` 有設定時覆蓋這張表。

### 10.2 限制

- `events.short_suspended` 期間（`start_date` 至 `end_date`，含）不得融券賣出。
- 平盤下：前一交易日的官方收盤價等於當日跌停價時（marketdata `daily`），當天融券賣出的委託價不得
  低於 `ref_price`，也不得用市價單。ETF 類不受限。
- 2022-10-21 → 2023-02-23：前一交易日收盤跌幅達 3.5%（`close × 1000 ≤ ref_price × 965`）的股票與
  TDR，同樣不得低於 `ref_price`。這項臨時措施的最後適用日未經官方來源確認（信用 §6）。

### 10.3 利息與回補

- 券商付給客戶的利息 = `round((保證金 + 擔保價款) × credit.short_credit_rate × 日數 ÷ 365)`，日數
  算法同融資。
- 融券買進依先進先出回補批次，部分回補時保證金與擔保價款依股數比例分攤（算法同 9.3）。
- 現券償還、標借與議借費用不模擬。
- 期限與展延同融資。

### 10.4 股東會與除權息前的強制回補

`events.short_suspended` 的 `start_date` 是最後回補日（信用 §3.6）。當天日結時仍未回補的融券部位，
次一交易日開盤前送出強制買進委託（規則同 12.4）。因此融券部位不會跨過除權息日，不需要股利補償。

## 11. 資券相抵

`account.credit_offset_enabled`（預設 true）時，日結依時間順序把同一商品當天的 `MarginBuy` 與
`ShortSell` 成交配對（順序不拘），配對的部分（信用 §5）：

- 不開立融資、融券批次，不收自備款與保證金，不計利息。
- 仍收買賣手續費、融券手續費、一般稅率的證交稅。
- 兩腿計入同一個交割日，淨額為差價。

商品在停資或停券期間不配對。沒有配對的部分依第 9、10 節開倉。

## 12. 維持率、追繳與處分

法規見信用 §4。

### 12.1 評價價格

官方收盤價（marketdata `daily.close`）。沒有收盤價時：`close_bid_px > ref_price` 用買價；
`close_ask_px < ref_price` 用賣價；否則用 `ref_price`。當天沒有 `daily` 列時用最近一次的評價價格。

### 12.2 整戶維持率

每個交易日日結時：

```text
維持率 = (Σ 融資股數 × 評價價格 + Σ (擔保價款 + 保證金))
         ÷ (Σ 融資金額 + Σ 融券股數 × 評價價格)
```

以有理數比較，不捨入。沒有信用部位時不計算。除權息前的擔保品市值調整（信用 §4.1）不模擬。

### 12.3 追繳

| 事件 | 行為 |
| --- | --- |
| `T` 日整戶維持率 < `credit.call_threshold`（預設 130%） | 建立追繳紀錄，記下各批次中單獨計算維持率也低於門檻者。通知在 `T` 之後第 `credit.notice_lag_days`（預設 1）個交易日送達；補繳期限日是送達日起算的第 `credit.grace_days`（預設 2）個交易日，送達日算第一天。預設值下期限日是 `T+2` |
| 期限日日結，整戶維持率仍低於門檻 | 次一交易日（預設 `T+3`）起處分追繳紀錄中的批次 |
| 期限日日結，整戶已回到門檻以上 | 暫不處分，紀錄保留；之後任一天日結又低於門檻，次一交易日起處分 |
| 整戶維持率 ≥ `credit.cancel_threshold`（預設 166%） | 取消追繳紀錄 |

模擬帳戶不能補繳現金或抵繳證券；要解除追繳，策略只能了結部位。

### 12.4 強制委託

處分、到期、強制回補產生的委託在交易日開盤前送出，參加開盤集合競價：

- 融資批次：賣出，限價為當天跌停價。融券批次：買進，限價為當天漲停價。無漲跌幅的商品用可下的
  最低／最高價。
- 類別為 `MarginSell`／`ShortCover`，標記 `forced`，不經策略，也不受資金檢查限制。
- 當天沒有全部成交時，剩餘量在次一交易日重送，最多連續 6 個交易日；仍未成交則 run 失敗。
- 成交後照一般規則結算。違約金不模擬。

## 13. 公司行動

來源是 marketdata `corp_actions`（現股 §5）。**權益以除權息日前一個交易日收盤後的部位為準**（含
尚未交割的買進，不含已賣出的），現股與融資部位都算。

| `action` | 處理 |
| --- | --- |
| `dividend`，`cash_dividend` 有值 | 應收現金股利 = `floor(股數 × 每股股利)`；發放日入帳。每股股利由 float64 轉成 1e-8 元的整數，轉換不是精確往返時失敗 |
| `dividend`，`stock_dividend` 有值 | 配發股數 = `floor(股數 × stock_dividend ÷ 10)`；不足一股的部分按面額折現：`floor(畸零股數 × 10)` 元。新股是成本為 0 的批次，交付日入帳，交付前不可賣出。非 10 元面額的股票（`f1_non10_par`）需要補充資料 |
| `rights` | 不產生分錄（不模擬認購） |
| `split`、`par_change` | 每個批次的股數乘以 `n`，`n = round(before_price ÷ ref_price)`；總成本不變 |
| `reverse_split` | 每個商品的總股數除以 `n = round(ref_price ÷ before_price)`，不足一股的部分以 `ref_price` 折現並標記 `approx` |
| `reduction_loss`、`reduction_cash` | 需要補充資料：減資比例、每股退還金額、退款日 |

`n` 與價格比的相對誤差超過 1% 時視為無法判定，需要補充資料。

### 13.1 marketdata 沒有的事實

| 事實 | 預設 | 設定 |
| --- | --- | --- |
| 現金股利發放日 | 除息日後第 `corporate_actions.cash_pay_lag_days`（預設 30）個日曆日之後的第一個交割日，標記 `approx` | 補充資料可指定確切日期 |
| 股票股利交付日 | 同上，使用 `corporate_actions.stock_credit_lag_days`（預設 30） | 同上 |
| 減資比例、退還金額、退款日 | 無 | 補充資料；或 `corporate_actions.missing_terms = "approximate"` |
| 反分割的畸零補償 | 以 `ref_price` 折現，標記 `approx` | 補充資料 |
| 合併、股份轉換、下市 | 無 | 補充資料 |

- **補充資料**（`corporate_actions.overrides`）：以 `(symbol, ex_date, action)` 為鍵，提供上表的
  確切值。有補充資料時不標記 `approx`。
- **持有部位而缺少必要事實時，run 失敗**，錯誤訊息列出商品、日期與缺少的欄位。沒有部位時事件
  直接略過。
- `missing_terms = "approximate"` 時，減資比例由價格反推（面額 10 元）：彌補虧損
  `r = 1 − before_price ÷ ref_price`；退還股款 `r = (ref_price − before_price) ÷ (ref_price − 10)`，
  每股退還 `10 × r` 元。結果標記 `approx`。
- 持有的商品從 `instruments` 消失（下市、合併）時，部位保留並以最後的評價價格計價，每天記錄診斷
  `stale_position`。

### 13.2 二代健保補充保費

`account.nhi_enabled`（預設 false；自然人帳戶應設為 true）。同一除權息日的現金股利加上股票股利
（按面額 10 元計）為一次給付；給付 ≥ 20,000 元時，保費 =
`round_half_up(min(給付, 10,000,000) × 0.0211)`，於現金股利發放日扣除（現股 §5.7）。

股利所得稅、匯費不模擬。

## 14. 成本與損益

台灣沒有法定的成本計算方法（現股 §6.1）。本系統的慣例：

- 現股批次先進先出。批次總成本 = 買進價金 + 分攤到的買進手續費。
- 賣出的已實現損益 = 賣出淨額（價金 − 分攤的手續費 − 證交稅）− 釋出批次的成本。部分釋出時成本
  依股數比例分攤（最大餘數法）。
- 當沖與資券相抵配對的損益由配對的兩腿直接計算。
- 融資：已實現損益 = 賣出淨額 − 買進成本 − 融資利息。融券：賣出淨額 − 融券手續費 + 利息 − 買進
  成本。
- 現金股利記為收入，不調整成本。補充保費、借券費記為費用。
- 減資退還股款沖減成本；沖減後為負的部分記為已實現利得。

權益（每個交易日日結後）：

```text
權益 = cash + Σ 待交割款 + Σ 應收股利
     + Σ 現股股數 × 評價價格
     + Σ (融資股數 × 評價價格 − 融資金額)
     + Σ (擔保價款 + 保證金 − 融券股數 × 評價價格)
```

尚未入帳的融資利息與融券利息不計入每日權益，於清償時認列。平均成本是由批次推導的報表欄位，不是
狀態。
